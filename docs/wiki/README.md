## 1. 编写口径（怎么保证不是空话）

- **结论来源**：仓库里的实际命令、模板与判定规则；关键行为都在本机跑过一遍（生成、校验、建页、认领、汇总、清理）。
- **判定编号**：文中出现的 `A1xx / H1xx / F1xx / V1xx / G1xx / C2xx / P1–P19` 都是系统真实输出的判定编号，
  看到红项时按编号回查 [`业务规则与状态.md`](业务规则与状态.md) 第 6 节。
- **不写推测**：没有实现的能力（账号、看板、远程流水线）在文中明确标注「没有」。
- **口径唯一**：名词以 [`术语表.md`](术语表.md) 为准，规则以 [`业务规范与口径.md`](业务规范与口径.md) 为准。

## 5. 维护规则

1. **一处改动，多处同步**：判定规则变了 → 先改 `业务规则与状态.md`，再改代码与本文相关描述；命令变了 → 改 `功能清单.md` 与对应业务域页。
2. **不复制规则原文**：文中只引用判定编号与口径，不复述整段实现细节，避免两套口径。
3. **文件增删要改本页**：第 2、3 节的表格是唯一的目录真源。
4. **链接必须可达**：本目录内所有相对链接都指向本目录内实际存在的文件；改文件名时全局搜索替换。
5. **不写「待补」当结论**：确需留空（如业务操作手册）必须说明留空原因与替代文档。

## 6. 怎么自己核对一条结论

任何一条说法都可以用三条命令验一次（在目标项目目录内）：

```sh
node <工具>/bin/dsh-plugin-harness-cli.js doctor      # 环境与工具是否健康
node <工具>/bin/dsh-plugin-harness-cli.js check       # 规则的实际输出（编号 + 级别）
bash scripts/gate.sh                                  # 门禁的实际链路
```

若文档与命令输出不一致：**以命令输出为准**，并在同一次改动里修正文档。
