# 业务风险与现场现象

> 读者：实施、业务人员，**现场作业前通读一遍**。
> 结构固定：**现场会看到什么现象 → 对业务有什么影响 → 现在能怎么规避**。
> 「现象」都来自真实行为；「规避」都是当前就能做的，不含未实现的计划。

## 1. 安装与部署

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 生成时报「不可写」/ 直接失败 | 装不起来，误以为工具坏了 | 确认在目标项目目录内、有写权限；受限环境换目录或申请权限 |
| 平台里看不到工具/命令 | 以为没装上，重复安装 | 先重启平台；再核对注册路径与安装目录是否一致 |
| 平台启动报插件加载失败 | 平台起不来，影响所有人 | 先移除注册项恢复启动，再修路径；保留注册文件备份 |
| 换机器后工具在、平台不认 | 集成失效，退回手工 | 平台注册项里的路径要跟着改；命令行方式不受影响 |

## 2. 生成与覆盖

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 二次执行大量「KEEP」 | 以为没生效 | KEEP 即「已存在、保留」；确认内容无误即可 |
| 想覆盖却覆盖不了 | 卡在旧内容上 | 结构文件加显式覆盖参数；状态文件要连状态一起覆盖，且谨慎 |
| 进度日志/功能清单被整文件替换 | 历史丢失，无法追溯 | 状态文件只增量维护；覆盖前备份，覆盖后核对条数 |
| 入口地图被手改后又被重生成覆盖 | 人工补充丢失 | 入口地图只由配置生成；补充内容放 `docs/` 并加链接 |

## 3. 校验与门禁

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 首次校验一屏红 | 误判「工具坏了」，浪费排查时间 | 先确认是否已生成骨架；未生成时的红项是预期的 |
| 退出码 2 被当成「有违规」 | 改错方向（去改业务文件） | 2 = 工具/环境坏了，先修环境；1 才是业务违规 |
| 门禁显示「跳过 lint / 测试」 | 以为过了，实际没测 | 没配置命令时门禁只跳过；交付前必须显式配置并确认执行过 |
| 只有警告，没人处理 | 警告累积，最后变成事故 | 交付前用严格模式跑一次，把警告清零或写明接受理由 |
| 生成了 CI 文件却没人跑 | 以为有流水线，实际没有 | CI 只是骨架：补仓库、凭据、镜像，并确认触发过一次 |
| 缺 python3 时风格门禁静默失效 | 风格问题流入主干 | 交付前确认风格能力可用；流水线里不要写「忽略失败」 |

## 4. 任务页与文档

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 新建任务页校验全红 | 以为页面模板坏了 | 骨架必须填 DDD/SDD/TDD；这是设计 |
| 总进度和步骤对不上 | 汇报数字失真 | 不手填总进度；只改步骤百分比 |
| 「总览过期」 | 领导看到的看板是旧的 | 每次改完页面跑一次汇总命令；交付前必须一致 |
| 任务页与文档说法不一致 | 评审时各说各话 | 同一轮改两侧；以契约编号为锚点 |
| 页面堆了几十个任务 | 打开慢、重点淹没 | 用保留策略清理旧页面（先预览）；长期结论留在任务日志 |
| 标「完成」被拒 | 交付节奏被打断 | 要么补完步骤与用例，要么如实标「待验收」 |
| UI 设计稿被 P20 拦 | 交付前发现视觉不统一 | 只用 antd 令牌与组件；改设计稿后重跑校验 |
| 方案未确认就被拦（P21 / progress 退出码 1） | 任务卡住不动 | 先跑 `plan --confirm --by "人"`，再推进度 |
| 进度记录与总览对不上 | 看板数字失真 | 只用 `progress` 更新，不要手改页面 |
| 改了 docs 之后进度被拒 | 任务卡住 | 重新跑 `review` 再 `plan --confirm --by "人"`，确认后继续 |

## 5. 并行协作

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 第二个任务被拒（并行上限 1） | 以为系统不支持并行 | 默认就是单任务；要并行先由负责人调大上限 |
| 「已被认领」 | 两个人重复做同一件事 | 换任务；确需接管让对方先释放 |
| 「范围冲突」 | 两人改同一批文件，合并冲突 | 开工前把范围写清；冲突就拆小或串行 |
| 范围空着没人管 | 冲突拦不住，最后靠人吵 | 认领时必须写范围；校验会给警告提醒 |
| 「已完成却还占着认领」 | 挡住后续任务 | 收工即释放；交付前统一清一次 |
| 僵尸认领（心跳超时） | 以为有人在做事，实际没人 | 校验只警告；确认无人后手动清理 |

## 6. 平台集成（可选）

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 工具调用报错但命令行正常 | 集成层问题，不是规则问题 | 先命令行复现；再查平台注册路径、运行环境差异 |
| 相对路径在两处表现不同 | 结果落在错误目录 | 工具参数省略时用会话工作目录；重要操作显式传目录 |
| 平台升级后工具消失 | 集成断档 | 升级后做一次加载冒烟；保留安装记录 |

## 7. 组织与流程

| 现象 | 业务影响 | 现在能怎么规避 |
|---|---|---|
| 口头说「做完了」 | 验收时无据可查 | 完成必须有证据；门禁与页面才是结论 |
| 规则写在聊天里 | 新人不认，重复踩坑 | 规则只认文件；聊天结论要落成文档或判定 |
| 两人对同一名词理解不同 | 需求与验收错位 | 先查术语表；有分歧先改口径页 |
| 没有自动化触发 | 检查全靠自觉 | 见「质量与交付卡点」的人工清单，逐项留痕 |

## 8. 一页速记（现场先看这五条）

1. 红项先看编号：`A/H/F/V/G` 是结构、`C` 是配置与认领、`P` 是任务页与文档。
2. 退出码 2 不要改业务文件。
3. 新建任务页失败是正常的，填完才通过。
4. 进度只改步骤百分比，改完追加记录、同步总览。
5. 并行先认领、写清范围、收工释放。
