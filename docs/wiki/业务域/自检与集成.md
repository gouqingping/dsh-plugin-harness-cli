# 业务域：自检与集成

> 所属域功能点：F7.1–F7.4。上游：无。下游：交付验收的第一步就是自检。

## 1. 能做什么

| 功能点 | 一段话 |
|---|---|
| F7.1 工具自检 | 检查 7 件事：运行环境版本、模板齐不齐、模板能否渲染、配置是否可读、目标目录可不可写、风格引擎是否可用、是否在 git 仓库里。 |
| F7.2 以工具形式供模型调用 | 装进平台后，模型可以像调用其他工具一样调用它（11 个工具 + 10 条斜杠命令，含业务 wiki、任务总览与 `/harness-cli-help`）。 |
| F7.3 跨环境安装 | 一条安装脚本或手动几步，把工具放到平台依赖目录并注册。 |
| F7.4 卸载与回滚 | 删注册项与目录即可；命令行能力不受影响。 |

## 2. 怎么触发

```sh
node <工具>/bin/dsh-plugin-harness-cli.js doctor        # 自检
```

平台集成后可用（工具名示意）：`harness_cli_init`、`harness_cli_page`、`harness_cli_check`、`harness_cli_agents`、`harness_cli_doctor`、`harness_cli_style`；
以及斜杠命令 `/harness-cli-init`、`/harness-cli-check`、`/harness-cli-doctor`。

## 3. 自检 7 项与含义

| 项 | 通过标准 | 不通过时先做什么 |
|---|---|---|
| 运行环境 | 版本满足最低要求 | 升级运行环境 |
| 模板 | 全部 21 份模板齐备 | 重装/补全工具目录 |
| 渲染 | 全部模板可正常渲染 | 同上；可能是安装不完整 |
| 配置 | 配置文件可解析 | 修配置语法 |
| 可写 | 目标目录可写 | 改权限或换目录 |
| 风格引擎 | 随包引擎可用（需 python3） | 装 python3；影响面仅风格能力 |
| git | 在 git 仓库内 | 无 git 只是警告：门禁只能人工触发 |

## 4. 规则

1. **先自检再校验**：自检报错（退出码 2）时不要继续改业务文件。
2. **警告不等于通过**：没有 git 时门禁不会被自动触发，交付前要人工跑。
3. **注册只影响平台**：删掉注册项，命令行仍然可用；工具本身不是平台服务。
4. **集成不改变规则**：平台调用与命令行调用走同一套判定与退出码。

## 5. 失败现象与处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 「不可写」 | 当前目录只读（含沙箱环境） | 换到有写权限的项目目录再跑 |
| 「不是 git 仓库」 | 只是警告 | 需要自动门禁就先建仓库并接流水线 |
| 「风格引擎不可用」 | 本机没有 python3 | 装 python3；不影响生成与校验 |
| 平台里看不到工具 | 未注册或注册路径失效 | 检查注册项与安装目录是否一致，重启平台 |
| 平台启动报插件加载失败 | 入口文件路径不对或文件损坏 | 先移除注册项恢复启动，再修路径 |
