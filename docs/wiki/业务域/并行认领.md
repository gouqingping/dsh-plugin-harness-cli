# 业务域：并行认领

> 所属域功能点：F5.1–F5.5。上游：功能清单的并行上限、任务页目录。下游：校验门禁、项目门禁。

## 1. 能做什么

| 功能点 | 一段话 |
|---|---|
| F5.1 认领任务 | 声明「这个任务我在做、我会改这些路径」，写进仓库，别人看得到。 |
| F5.2 续心跳 | 长任务定期报平安；心跳超时会被判成「死掉的会话」。 |
| F5.3 释放认领 | 收工释放；没收工就释放会让任务变成「无人认领」。 |
| F5.4 认领一致性校验 | 每个进行中任务都必须有认领，两份认领的路径不能重叠。 |
| F5.5 清理陈旧认领 | 结束的任务或心跳过期的认领可以清理（可先预览）。 |

## 2. 怎么触发

```sh
node scripts/claim.js add F-003 --owner "会话A/张三" --scope src/auth --scope docs/
node scripts/claim.js list
node scripts/claim.js heartbeat F-003 --owner "会话A/张三"
node scripts/claim.js release F-003
node scripts/claim.js verify
node scripts/claim.js prune --dry-run
```

## 3. 规则

1. **先认领再开工**，不是先做再补。
2. **独占创建**：两个人同时抢同一个任务，只有一个成功。
3. **并行上限**：认领数量不能超过任务队列里的并行上限（默认 1）。
4. **范围不重叠**：两份认领的路径相同或互为前缀即冲突。
5. **只改自己范围**：跨范围要先释放再重新认领。
6. **心跳有效期**：超过配置时长没心跳只警告、不自动删；确认后才手动清理。
7. **认领指向真实任务**：认领必须对应功能清单里存在且未结束的任务。

## 4. 产出

```
docs/claims/<F-xxx>.json    每份认领：任务、认领人、第几轮、范围、开始时间、心跳时间
docs/claims/README.md       协议说明（生成物）
scripts/claim.js            认领工具（生成物）
```

## 5. 失败现象与处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 「已被认领」 | 别人在做 | 换任务；确实要接管先让对方释放 |
| 「并行上限 1」 | 已经到了并行预算 | 先释放，或由负责人调大上限 |
| 「范围冲突」 | 两份认领改同一批文件 | 换范围或拆小范围 |
| 「in_progress 没有认领」 | 有人开工没登记 | 补认领；查清是谁在改 |
| 「已完成却还占着认领」 | 收工没释放 | 释放掉，避免挡住后续任务 |
| 「心跳 20h 前」 | 可能是死掉的会话 | 先确认没人做，再清理 |
