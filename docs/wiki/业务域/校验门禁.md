# 业务域：校验门禁

> 所属域功能点：F2.1–F2.6。上游：初始化产出的文件。下游：任务页与进度、规范文档、并行认领的规则都在这里被调用。

## 1. 能做什么

| 功能点 | 一段话 |
|---|---|
| F2.1 入口与配置校验 | 入口地图八节齐不齐、引用的文件在不在、是否与配置同源。 |
| F2.2 骨架与状态校验 | 环境脚本可执行、门禁脚本含「遇错即停」、进度日志有「下一步行动」、任务队列并行上限合法、骨架文件齐备、CI 骨架存在。 |
| F2.3 范围与证据校验 | 功能清单字段齐全、编号唯一、状态合法、并行不超上限、完成的必须有证据、依赖不悬空不成环。 |
| F2.4 版本说明校验 | 四个板块齐全、更新内容有编号条目、不留「待补」、验证标准可勾选。 |
| F2.5 只读与退出码 | 校验不改任何文件；退出码 0/1/2 就是结论；严格模式下警告也算失败。 |
| F2.6 项目门禁一键跑 | 一条命令串起 lint、测试、并行上限与认领一致性，任一步失败即停。 |

## 2. 怎么触发

```sh
node <工具>/bin/dsh-plugin-harness-cli.js check          # 只读校验
node <工具>/bin/dsh-plugin-harness-cli.js check --strict  # 警告也算失败
bash scripts/gate.sh                                     # 项目门禁
```

## 3. 判定分组（看到编号就知道该改哪）

| 前缀 | 管什么 | 典型红项 |
|---|---|---|
| A1xx | 入口地图 | 缺章节、失去效链接、与配置不同源、定位仍是占位 |
| H1xx | 骨架与状态 | 缺环境脚本、门禁没「遇错即停」、进度日志缺下一步、并行上限非法、缺认领脚本 |
| F1xx | 范围与证据 | 缺字段、编号重复、同时进行中超过上限、完成没证据、依赖成环 |
| V1xx | 版本说明 | 缺板块、无编号条目、留待补 |
| G1xx | 忽略规则 | 缺八条必需规则 |
| C1xx / C2xx | 配置与认领 | 缺配置、用了旧文件名、认领缺失或范围重叠 |
| P1xx / P13–P19 | 任务页与规范文档 | 规划编号断档、契约缺格、用例没挂契约、总览过期、文档与页面不一致 |

## 4. 规则

1. **只读**：校验不写盘；修复交给生成命令或人。
2. **失败要能指向下一步**：每条红项都带可执行提示（改哪个文件、跑哪条命令）。
3. **不静默降级**：配置读不动、模板缺失 → 退出码 2，不猜默认值继续跑。
4. **警告与错误分开**：警告不阻断，严格模式下才升级为失败。
5. **规则可追溯**：每条判定都有对应失败用例，规则改动必须同时补用例。

## 5. 失败现象与处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 一屏「缺少四件套」 | 目标目录还没生成骨架 | 先跑生成命令；这是预期结果，不是工具坏了 |
| 退出码 1 + 若干红项 | 有可预期违规 | 按判定 id 逐条修，重跑 |
| 退出码 2 | 工具或配置本身坏了 | 先自检；不要改业务文件 |
| 大量 P 类红项 | 任务页还是骨架 | 按页内提示填 DDD / SDD / TDD / 文档 |
| 只有警告 | 不阻断 | 交付前建议用严格模式再跑一次 |
