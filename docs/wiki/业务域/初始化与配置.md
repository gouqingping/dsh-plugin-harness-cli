# 业务域：初始化与配置

> 所属域功能点：F1.1–F1.4。上游：无。下游：本域产出的文件被所有其他域读取。

## 1. 能做什么

| 功能点 | 一段话 |
|---|---|
| F1.1 一键生成项目骨架 | 在仓库根目录执行一次，就把「入口地图、环境脚本、门禁、功能清单、进度日志、任务队列、任务日志、版本说明、CI 骨架、忽略规则」一次生成齐。 |
| F1.2 启用任务页能力 | 加上开关后，额外生成任务页目录、模板、总览页与页面校验脚本；之后每个任务一页。 |
| F1.3 由配置重生成入口地图 | 入口地图不手写：改配置 → 重生成 → 行数与链接自动校验。 |
| F1.4 最小覆盖配置 | 配置只写要改的字段，其余走默认；旧文件名仍能读，读到就提示改名。 |

## 2. 怎么触发

```sh
# 生成骨架（不启用任务页）
node <工具>/bin/dsh-plugin-harness-cli.js init

# 生成骨架并启用任务页
node <工具>/bin/dsh-plugin-harness-cli.js init --preset prototype

# 已有项目补开任务页（只补缺失项，不覆盖已有内容）
node <工具>/bin/dsh-plugin-harness-cli.js init --preset prototype

# 只重生成入口地图
node <工具>/bin/dsh-plugin-harness-cli.js agents
```

## 3. 规则

1. **不覆盖**：已存在的非空文件默认保留；要覆盖必须显式 `--force`。
2. **状态文件例外**：功能清单、进度日志、任务日志、任务队列即使 `--force` 也不覆盖，必须显式 `--force-state`。
3. **只补缺失**：老项目补开任务页时，只补缺失的页面与脚本，并回写开关，不重写已有文件。
4. **配置是唯一入口**：路径、命令、目录、约定、禁止事项、完成定义都从配置读；改文案不改生成物。

## 4. 产出文件（一次 init）

| 文件 | 用途 |
|---|---|
| `harness-cli.json` | 唯一的配置入口 |
| `AGENTS.md` | 入口地图（生成物，不手改） |
| `init.sh` | 环境初始化（幂等） |
| `scripts/gate.sh` | 门禁脚本 |
| `docs/feature_list.json` | 范围：做什么、验收标准、证据 |
| `claude-progress.md` | 进度日志（跨会话） |
| `task_queue.json` | 任务队列与并行上限 |
| `docs/current.md` | 任务日志（顶部追加） |
| `docs/summary.json` / `docs/graph.json` | 当前任务与模块依赖 |
| `docs/specs/README.md` | 规范文档约定 |
| `docs/claims/README.md` | 认领约定 |
| `docs/adr/ADR-0001-*.md` | 第一个设计决策 |
| `_VERSIONS/v<版本>.md` | 版本说明（业务白话） |
| `.harness/<项目>_ci.yaml` | CI 流水线骨架 |
| `.gitignore` | 八条必需忽略规则（追加，不覆盖） |
| `README.md` | 项目说明 |
| 任务页能力 | `prototype/README.md`、`prototype/_template/progress.html`、`prototype/progress.html`、`scripts/prototype-check.js` |
| 认领能力 | `scripts/claim.js` |

## 5. 失败现象与处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 输出大量「KEEP」 | 文件已存在，被保留 | 正常；确认内容符合预期即可 |
| `未知 preset` | 开关名写错 | 用受支持的开关名（当前仅任务页） |
| `配置有问题，先修 harness-cli.json` | 配置字段类型或必填项不对 | 按列出的问题逐条改 |
| 入口地图行数警告 | 写成了手册 | 把细节拆到 `docs/`，入口只留链接 |
| 退出码 2 | 工具或用法有问题 | 先跑自检，不要改业务文件 |
