# 业务域：规范文档

> 所属域功能点：F4.1–F4.3。上游：任务页（同一次创建）。下游：校验门禁的文档一致性判定。

## 1. 能做什么

| 功能点 | 一段话 |
|---|---|
| F4.1 随任务生成四份文档 | 建任务页时一起落盘：提案、契约、设计、任务规划；已存在的不覆盖。 |
| F4.2 文档与页面一致 | 步骤数与标题、契约编号集合必须与页面一致，防止「页面说 A、文档说 B」。 |
| F4.3 设计文档含 DDD 四段 | 限界上下文 / 统一语言 / 聚合与实体 / 不变量，四段缺一不可。 |

## 2. 文档结构与读者

| 文件 | 内容 | 主要读者 |
|---|---|---|
| `docs/specs/<任务>/proposal.md` | 用户原话、为什么做、范围与非目标、验收 | 产品、项目负责人 |
| `docs/specs/<任务>/spec.md` | 契约 `S-01` 起：输入 / 输出 / 错误语义 / 验收标准 | 开发、测试 |
| `docs/specs/<任务>/design.md` | 限界上下文、统一语言、聚合与实体、不变量、方案取舍 | 开发、架构 |
| `docs/specs/<任务>/tasks.md` | 任务规划 1..N，每步标注落地的契约编号 | 开发、实施 |

## 3. 拆分顺序（不许颠倒）

1. **先划线（DDD）**：这个任务属于哪个边界，边界外的东西不碰；写出统一语言与不变量。
2. **再定契约（SDD）**：每条行为写清输入、输出、错误语义、验收标准；错误语义必须写。
3. **再排步骤（规划）**：把契约落到步骤，每步标注落哪条契约。
4. **最后推页面**：页面与文档同一轮改完。

## 4. 规则

1. **一处真源**：契约编号与步骤以页面与文档「双方一致」为准，任何一侧改动都要同步另一侧。
2. **不留待填**：四份文档里出现「待填」即判失败。
3. **编号稳定**：`S-xx` 一旦被页面与用例引用，就不要改号；改内容不改号。
4. **不覆盖已有文档**：再次建同名任务只补缺失文件，不覆盖人工内容。

## 5. 失败现象与处理

| 现象 | 含义 | 处理 |
|---|---|---|
| 「缺少 proposal.md」 | 老任务没文档 | 再跑一次建页命令，只补缺失文档 |
| 「文档还没填完」 | 有「待填」或空文件 | 补内容；这是交付前必须清掉的 |
| 「tasks.md 有 3 步，页面有 4 步」 | 两侧不同步 | 先定步骤，再同步页面与文档 |
| 「spec.md 缺少契约 S-02」 | 页面有、文档没有 | 补文档或删页面里的多余契约 |
| 「design.md 缺少 DDD 小节」 | 少了聚合或不变量 | 补小节，不要只写一句话标题 |
