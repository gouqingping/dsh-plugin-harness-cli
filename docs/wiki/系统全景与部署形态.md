# 系统全景与部署形态

> 读者：实施、售前。只讲业务与部署，不讲代码。
> 目标：回答「由哪几部分组成、装在哪、数据存在哪、怎么配合、断网或重启会怎样」。

## 1. 由哪几部分组成

| 组成 | 是什么 | 是否需要单独部署 |
|---|---|---|
| 命令本体 | 一套命令行程序（生成骨架、校验、建任务页、认领、风格检查） | 否，随项目目录分发 |
| 模板库 | 生成物的文案与结构（21 份） | 否，随命令本体 |
| 生成物 | 落在客户仓库里的配置与文档（入口地图、功能清单、门禁脚本、任务页、规范文档…） | 是，这是交付物 |
| 可选集成 | 装进 DSH 后成为模型可调用的工具与斜杠命令 | 是，可选 |

一句话：**它是一个「生成 + 校验」的工具，不是一个需要常驻运行的服务。**

## 2. 装在哪

三种形态，按客户环境选一种即可：

**形态 A · 源码直接运行（最轻）**
- 把工具目录放到任意位置，在有 Node.js 的机器上直接运行。
- 适合：临时评估、单机试用、离线环境。

**形态 B · 装进 DSH（平台集成）**
- 工具目录挂到 DSH 的依赖目录下，并在 DSH 的插件注册文件里加一条入口。
- 装好后平台里多出 11 个工具与 10 条斜杠命令，模型可以直接调用（含业务 wiki、任务总览与帮助）。
- 适合：已使用 DSH 的团队，让 AI 按同一套规则干活。

**形态 C · 整目录拷走（离线交付）**
- 工具目录是自包含的：拷到另一台机器即可运行，不需要联网安装依赖。
- 适合：内网、隔离网、客户现场。

> 三种形态用的是同一份工具与模板，行为一致；差别只在「谁触发」。

## 3. 数据存在哪

- **全部存在客户仓库的文本文件里**：配置（1 份）、入口地图、功能清单、进度日志、任务队列、任务页、规范文档、门禁脚本、版本说明、CI 骨架。
- **没有数据库、没有服务端、没有缓存目录、没有用户表**。
- 工具运行期**不写任何全局状态**：不改系统配置，不写用户目录（插件注册那一条是安装动作，不是运行期行为）。
- 因此：**数据可版本化、可 diff、可审计**；迁移就是拷目录。

## 4. 几部分之间怎么配合

```
配置（harness-cli.json）
   │  决定命名、路径、命令、并行上限、开关
   ├──> 入口地图 AGENTS.md          （新人/新会话的导航）
   ├──> 功能清单 docs/feature_list.json（做什么、验收标准、证据）
   ├──> 进度日志 + 任务日志         （做到哪、下一步）
   ├──> 任务队列 task_queue.json    （并行上限 wipLimit）
   ├──> 任务页 prototype/           （状态与进度，给人看）
   ├──> 规范文档 docs/specs/        （DDD 设计 / SDD 契约 / 任务规划）
   ├──> 认领 docs/claims/           （谁在做、改哪些文件）
   └──> 门禁 scripts/gate.sh + 校验命令（能不能交付）
```

配合关系有两条硬线：
1. **入口唯一**：人和 AI 都从入口地图进，入口指向的文件必须真实存在（否则校验失败）。
2. **状态唯一**：范围看功能清单，进度看任务页，文档看 `docs/specs/`；同一件事不在两处各写一份（一致性由校验保证）。

## 5. 断网或重启会怎样

| 情形 | 影响 | 说明 |
|---|---|---|
| 完全断网 | 不受影响 | 零运行时依赖，不需要联网安装或调用外部服务 |
| 机器重启 | 不受影响 | 没有常驻进程、没有内存状态；文件在就一切在 |
| 会话中断 | 进度不丢 | 进度写在文件里，新会话读入口即可恢复 |
| 装进 DSH 后重启 | 工具自动恢复 | 平台启动时按注册项加载；未注册则不出现，命令行仍可用 |
| 工具目录被移动 | 生成物不受影响 | 生成物在客户仓库；只有平台注册项里的路径需要同步改 |
| 目标仓库换机器 | 拷目录即可 | 全部状态是文件，无外部依赖 |

## 6. 运行前置条件

| 条件 | 是否必需 | 缺失后果 |
|---|---|---|
| Node.js ≥ 18 | 必需 | 命令无法运行 |
| python3 ≥ 3.8 | 仅「代码风格与提交信息」需要 | 该能力报错退出（退出码 2），其余能力正常 |
| git 仓库 | 建议 | 缺省不影响生成与校验，但门禁只能在收尾时人工执行（自检会给警告） |
| 写权限 | 必需 | 无法生成或更新文件，校验会报不可写 |

## 7. 典型部署组合

| 客户情况 | 推荐形态 | 理由 |
|---|---|---|
| 单人评估 / 售前演示 | A | 零安装，现场就能跑 |
| 研发团队已用 DSH | B | AI 与人共用同一套规则 |
| 内网隔离、离线交付 | C | 无依赖、可拷贝、可版本化 |
| 多会话/多人并行开发 | B 或 C + 并行认领 | 认领与范围冲突在开工前被拦 |

> 安装与卸载的逐步操作见 `业务操作手册.md`；上线前检查见 `质量与交付卡点.md`。
