# 角色与场景

> 读者：售前、实施、项目负责人。讲清「谁在用、各自能做什么、不能做什么」，以及几类容易混淆的角色。

## 1. 角色总表

| 角色 | 典型人 | 能用什么 | 不能做什么 |
|---|---|---|---|
| 项目负责人 / 交付负责人 | 技术负责人、交付经理 | 生成骨架、跑校验、看门禁结果、决定并行上限、拍板验收 | 不能代替产品判断需求好坏；不能跳过校验直接宣称完成 |
| 开发 / 实施工程师 | 前端、后端、现场实施 | 新建任务页、填规范文档、推进步骤百分比、认领任务、跑风格检查 | 不能改别人认领范围；不能手改进度总数；不能删状态文件里的历史 |
| 产品 / 测试 | 产品经理、测试工程师 | 读功能清单与任务页；按「业务规则与状态」「验收与测试要点」判定是否通过 | 不能改代码范围；不能把「待验收」标成「完成」 |
| 业务 / 客户代表 | 业务方、客户接口人 | 读「一页纸速览」「术语表」「业务规范与口径」；确认业务口径 | 不看代码细节；不直接改仓库文件 |
| Agent（AI 执行者） | DSH / 其他编码 Agent | 读入口地图、按任务页与契约干活、调工具跑校验 | 不能绕过门禁；不能在无认领时开工；不能覆盖状态文件 |

> 关键区别：**Agent 是「执行者」，不是「决策者」**。它按文件里的规则执行；规则缺失是人的责任。

## 2. 每个角色的典型一天

**项目负责人**
1. 早上看总览页（`prototype/progress.html`）：进行中几个、各自多少进度。
2. 看校验结果：红的是哪几条、归谁。
3. 决定是否放行：门禁全绿 + 验收清单过 → 交付。

**开发 / 实施**
1. 读入口地图（`AGENTS.md`）→ 找到「做什么」在功能清单、「做到哪」在进度日志。
2. 认领任务（并行时）→ 建/打开任务页 → 从任务规划里拿一步开工。
3. 改完推进度百分比、补测试用例状态、追加一条进度记录。
4. 跑校验与门禁，红了就修，绿了再交给负责人。

**产品 / 测试**
1. 用「业务规范与口径」对齐名词，避免各说各话。
2. 按「业务规则与状态」确认状态流转是否合法。
3. 按「验收与测试要点」逐场景过，记录「怎么算过」的证据。

**业务 / 客户代表**
1. 只读三篇：一页纸速览（是什么）、术语表（叫什么）、业务规范与口径（怎么算）。
2. 对不上的地方提出口径变更，由产品落进文档，而不是口头约定。

## 3. 几类容易混淆的角色

| 容易混淆 | 实际区别 | 记法 |
|---|---|---|
| 「项目负责人」vs「开发负责人」 | 前者对**交付结果**负责（放行、验收），后者对**实现质量**负责 | 一个签字，一个写码 |
| 「实施」vs「开发」 | 实施负责把工具装到客户环境、把规范填进客户项目；开发写业务代码 | 实施让系统跑起来，开发让业务跑起来 |
| 「产品」vs「测试」 | 产品定「什么算对」，测试验「是否真的对」 | 一个定标准，一个验标准 |
| 「Agent」vs「开发」 | Agent 执行文件里写下的规则，开发决定规则与范围 | Agent 不拍板 |
| 「业务方」vs「客户接口人」 | 前者给业务口径，后者给验收签字 | 一个给内容，一个给结论 |
| 「使用系统的人」vs「被系统要求的人」 | 用工具生成配置的人，和被这套规范约束的全体开发者 | 少数人装，多数人守 |

## 4. 场景 → 角色矩阵

| 场景 | 主责 | 参与 | 说明 |
|---|---|---|---|
| 新项目接入 | 项目负责人 | 开发、Agent | 生成骨架、填配置、跑通一次校验 |
| 老项目补规范 | 实施 | 项目负责人 | 只补缺失项，不动已有状态 |
| 单任务交付 | 开发 | 产品、测试、Agent | 任务页五段 + 文档四件套 + 门禁 |
| 多会话并行 | 项目负责人定上限 | 开发 / 多个 Agent | 先认领再开工，范围不重叠 |
| 代码风格与提交 | 开发 | 交付 | 提交前检查，可自动修复 |
| 交付验收 | 项目负责人 | 产品、测试、业务 | 按场景清单逐条确认 |
| 现场演示 / 售前 | 售前 | 实施 | 用「一页纸速览」+ 演示一条真实任务 |

## 5. 权限与边界（没有账号体系）

这套系统**没有登录、没有角色权限**：谁能做什么，由「谁有仓库写权限」和「评审流程」决定。因此：

- 「不能做什么」靠**规则 + 校验**落地（例如：并行上限、范围重叠会被拒绝），不是靠账号。
- 想区分权限，请在代码托管平台侧做（分支保护、CODEOWNERS），本系统不重复实现。
- 多人并行时，**认领文件**是唯一的「在做什么」事实来源；口头分工不算。
